Pflegefassung. Sie behebt einen Fehler, der sich beim Aktualisieren zeigte.

## Behoben

- **Der Terminal-Befehl `silentinstaller` scheiterte** mit „No module named
  silentinstaller“. `install.sh` legt ihn als Verweis in `~/.local/bin` an; der
  Starter ermittelte sein Verzeichnis über den Namen, unter dem er aufgerufen
  wurde – und das war der Ordner des Verweises, in dem kein Python-Paket liegt.
  Verweise werden jetzt aufgelöst, auch mehrstufige.

  **Nicht betroffen:** der Menüeintrag, weil die `.desktop`-Datei den echten
  Pfad nennt, und das Debian-Paket, das ein eigenes Startskript mitbringt.

Geprüft sind jetzt alle vier Wege: über den Verweis, über einen Verweis auf den
Verweis, über den direkten Pfad und über den Menüeintrag.

## Aus 1.3.0 übernommen

- **Hinweis auf neue Fassungen.** Beim Start sieht SilentInstaller höchstens
  einmal am Tag bei GitHub nach und meldet, wenn es etwas Neueres gibt.
  Heruntergeladen oder installiert wird nichts. Gibt es nichts Neues, bleibt es
  still. Abschaltbar unter *Einstellungen ▸ Installation*.
- **Fassung neben dem Namen** in Fenstertitel und Kopfleiste.

## Aktualisieren

```bash
# Debian, Ubuntu und Co.
wget https://github.com/Stephan-Lefty/SilentInstaller/releases/download/v1.3.1/silentinstaller_1.3.1_all.deb
sudo apt install ./silentinstaller_1.3.1_all.deb

# Aus dem Quelltext, etwa unter Arch und Manjaro
cd SilentInstaller && git pull && ./install.sh
```

Eigener Katalog, Profile und Einstellungen bleiben erhalten – sie liegen in
`~/.config/silentinstaller/` und werden nicht angefasst.

## Noch offen

Die polkit-Passwortabfrage auf einem Debian-Desktop ist weiterhin ungeprüft;
im Container lief das Skript als root.
