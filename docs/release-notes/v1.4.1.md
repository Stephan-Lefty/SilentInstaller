Dringende Pflegefassung. Sie behebt einen Fehler, der apt vollständig lahmlegen
konnte – gemeldet aus der Community für GuideOS.

> **Wichtig für bereits Betroffene:** Ist der Widerspruch auf Ihrem System
> schon entstanden, hilft diese Fassung allein **nicht** weiter. `apt` bricht
> ab, bevor es zur Installation kommt – auch bei diesem Paket. Räumen Sie
> zuerst mit dem Skript weiter unten auf.

## Behoben

**Doppelte Paketquelle machte apt unbrauchbar.**

Brachte die Distribution eine der Fremdquellen bereits mit – etwa Brave unter
GuideOS –, legte SilentInstaller eine zweite Eintragung derselben Quelle mit
eigenem Signaturschlüssel an. apt verweigerte daraufhin jeden Dienst:

```
E: Conflicting values set for option Signed-By regarding source
   https://brave-browser-apt-release.s3.brave.com/ stable:
   /usr/share/keyrings/brave-browser-archive-keyring.gpg !=
   /usr/share/keyrings/silentinstaller-brave.gpg
E: The list of sources could not be read.
```

Betroffen war **nicht nur SilentInstaller**, sondern jeder spätere
`apt`-Aufruf – bis hin zur Installation dieses Pakets selbst.

Der Fix hat zwei Teile:

- **Vorher prüfen.** Steht dieselbe Paketquelle schon in einer anderen Datei,
  bleibt sie unangetastet. Es entsteht keine zweite Eintragung.
- **Selbstheilend beim nächsten Durchlauf.** Läuft SilentInstaller wieder,
  entfernt es seine eigene widersprüchliche Eintragung. Das setzt allerdings
  voraus, dass das Programm überhaupt startet – wer den Widerspruch schon hat,
  braucht zuerst den Weg unten.

Nachgestellt in einem Debian-Container mit vorinstallierter Brave-Quelle – der
Fehler tritt wortgleich auf, und nach dem Durchlauf läuft `apt update` wieder
fehlerfrei. Der Fix gilt genauso für Signal, Vivaldi und Visual Studio Code.

Außerdem: **GuideOS** wird ausdrücklich als Debian-Abkömmling geführt.

## Wer schon betroffen ist: erst aufräumen

Das Reparaturskript kommt ohne `apt` aus – genau darin lag ja das Problem:

```bash
curl -fsSLO https://raw.githubusercontent.com/Stephan-Lefty/SilentInstaller/main/apt-quellen-reparieren.sh
chmod +x apt-quellen-reparieren.sh
sudo ./apt-quellen-reparieren.sh            # zeigt nur an, was zu tun wäre
sudo ./apt-quellen-reparieren.sh --machen   # entfernt die Widersprüche
sudo apt update
```

Es betrachtet nur Dateien mit einem `silentinstaller-`Signaturschlüssel und
entfernt sie ausschließlich dann, wenn dieselbe Quelle anderswo bereits
eingetragen ist. Die Paketquelle der Distribution bleibt unberührt.

Wer lieber von Hand vorgeht:

```bash
sudo rm $(grep -rl silentinstaller- /etc/apt/sources.list.d/)
sudo apt update
```

Danach lässt sich diese Fassung normal installieren.

## Installation

```bash
wget https://github.com/Stephan-Lefty/SilentInstaller/releases/download/v1.4.1/silentinstaller_1.4.1_all.deb
sudo apt install ./silentinstaller_1.4.1_all.deb
```

Aus dem Quelltext, etwa unter Arch und Manjaro:

```bash
cd SilentInstaller && git pull && ./install.sh
```

## Berichtigung

Eine frühere Fassung dieser Anmerkungen behauptete, statt des Aufräumens
genüge „ein Durchlauf mit dieser Fassung“. Das war falsch: Solange der
Widerspruch besteht, lässt sich das Paket gar nicht erst installieren. Danke
an die Melderin für den Hinweis.
