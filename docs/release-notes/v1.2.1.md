Pflegefassung. Sie behebt vier Fehler, die nach 1.2.0 aufgefallen sind – zwei
davon beim Erstellen der Bildschirmfotos, einer beim Einrichten unter KDE.

## Behoben

- **Menüeintrag erschien unter KDE nicht.** `install.sh` rief nur
  `update-desktop-database` und `gtk-update-icon-cache` auf. Plasma führt sein
  Menü aber in einer eigenen Datenbank (ksycoca); der Eintrag tauchte deshalb
  erst nach einer Neuanmeldung auf. Der Installer stößt jetzt `kbuildsycoca6`
  bzw. `kbuildsycoca5` an, dazu `xdg-desktop-menu forceupdate` für XFCE und
  LXQt. Das Debian-Paket ist davon nicht betroffen: Es installiert systemweit,
  und dort liest KDE neue Einträge selbst ein.
- **`install.sh` meldete auch dann Erfolg, wenn nichts ankam.** Es prüft jetzt
  zum Schluss, ob Menüeintrag und Symbol tatsächlich liegen.
- **Einstellungsfenster hieß „Preferences“**, auch bei deutscher Oberfläche.
- **Falscher Platzhalter für den Benutzernamen**, wenn das Heimatverzeichnis
  unmittelbar unter der Wurzel liegt (etwa `/root`): Statt `/USER/…` steht dort
  jetzt `~/…`.

## Neu

- **Zehn Bildschirmfotos** der Oberfläche im README, aufgenommen unter Debian 13.
- **Auf Debian 13 geprüft:** Paketinstallation, Freischalten der `contrib`-,
  `non-free`- und `non-free-firmware`-Bereiche in den deb822-Quellen, alle vier
  Fremdquellen mit Signaturschlüssel und eine Probeinstallation daraus – alle
  Schritte fehlerfrei. Die Oberfläche startet und findet für alle 84 Einträge
  eine Quelle.

## Installation

```bash
wget https://github.com/Stephan-Lefty/SilentInstaller/releases/download/v1.2.1/silentinstaller_1.2.1_all.deb
sudo apt install ./silentinstaller_1.2.1_all.deb
```

Auf Arch, Manjaro und Co. weiterhin über den Quelltext:

```bash
git clone https://github.com/Stephan-Lefty/SilentInstaller.git
cd SilentInstaller && ./install.sh
```

## Noch offen

Im Container lief das Skript als root, `pkexec` kam nicht zum Zug. Die
polkit-Passwortabfrage auf einem Debian-Desktop ist weiterhin ungeprüft.
